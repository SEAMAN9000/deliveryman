# deliveryman

> 把一个项目做成可以对外分享的脱敏副本——一个给 Claude Code 等 AI 编程助手使用的 skill。

📖 English: [README.en.md](./README.en.md)

```bash
npx skills add SEAMAN9000/deliveryman
```

把项目交给别人之前，文件里常常留着不该外传的东西：密钥、本机路径里的用户名、内网地址、开发过程笔记、Word 文档属性里的作者名。deliveryman 先只读扫描，给出一张一览表，你确认后才在项目内生成一份干净的副本。源项目不会被改动，副本也不会被上传。

不止代码项目：报告、论文、PPT、文档这类成品同样适用。

## 什么时候用

项目做完要交给别人时，逐个文件检查哪里留着密钥、用户名或内部笔记，既费时间又容易漏。直接把整个文件夹发出去，对方会连同你的开发笔记和本机路径一起收到。deliveryman 把这次检查做成一张可以核对的表，再按对方的身份整理出一份副本。

✅ 适合：

- 要把代码项目交给同事或合作者，对方要看代码或接着改。
- 要把程序、报告、论文或 PPT 发给只使用或阅读的人。
- 准备公开一个项目，想先看清里面有哪些不该外传的内容。

❌ 不适合：

- 想把项目上传到代码托管网站或创建代码仓库：deliveryman 只生成本地副本，上传请用 git 或托管网站自己的工具。
- 想清掉 PDF、图片里的作者和拍摄信息，或 Office 文档正文里的敏感内容：这些内容它不检查，请在源文件里处理。
- 密钥已经提交进版本历史：副本不带版本历史，但原仓库里的记录还在，请更换密钥，并用 git 的历史改写工具清理。

## 用起来长什么样

下面是对一个只有 7 个文件的示例项目使用一次的对话记录，有删减。「用户：」后面是使用者说的话，「AI：」后面是助手的回复。

```text
用户：我想把这个项目发给同事看，帮我弄一个干净的版本

AI：这份干净版本是给同事做什么用的？这决定副本里带哪些文件。
    - 同事要看代码或接着改：带上源代码和全部说明文档（README、docs 里的文档），去掉密钥文件、个人信息和本机路径。
    - 同事只是使用或阅读：只带说明文档和成品，默认不带源代码，同样去掉密钥、个人信息和本机路径。
    - 两种各做一份：分别生成上面两个版本，放在两个文件夹里，你再挑着发。

用户：同事要看代码或接着改

AI：项目已扫描完，副本还没生成，需要你先看一眼下面的清单并确认。

    共 7 个文件：复制 5 个（其中替换敏感内容 1 个、含本机路径待裁决 1 个），不进副本 2 个（其中 1 个可以要求保留）。源项目只读，原文件没有任何改动。

    | 项目结构 | 处理 | 说明 |
    |---|---|---|
    | docs/ |  |  |
    | 　　guide.md | 复制 |  |
    | 　　setup.md | **复制，待你裁决** | 含本机路径（不会自动替换）：Windows 本机路径 ×1 |
    | src/ |  |  |
    | 　　config.py | **复制并替换** | 将替换：Windows 用户目录路径 ×1 |
    | 　　main.py | 复制 |  |
    | .env | 不进副本 | 密钥或密码文件 |
    | CLAUDE.md | 不进副本 | AI 协作文件，可要求保留 |
    | README.md | 复制 |  |

    需要你看的文件（2 个）：
    - docs/setup.md：含本机路径（不会自动替换）：Windows 本机路径 ×1
    - src/config.py：将替换：Windows 用户目录路径 ×1

    本次设定：按"给开发者"的方式打包（带源代码和全部说明文档），不保留 AI 协作文件。这个项目以前没打包过，没有沿用任何旧选择。

    需要你拿主意的有两条：

    1. docs/setup.md 里有一处你电脑上的路径。工具不会自动替换它，你确认后它会原样出现在副本里。
    2. CLAUDE.md（给 AI 助手看的项目说明）默认不带。如果同事也用 AI 助手接着改代码，可以让我留下。

    回 y 就表示你接受第 1 条的路径原样进入副本。你也可以回"调整"（比如"把 CLAUDE.md 也留下"）或"取消"。

用户：y，继续

AI：干净副本已经做好，放在项目里的 output/deliver/dev-2026-11-25-0330 文件夹，把这个文件夹整个发给同事就行。

    - 存密钥的 `.env` 和给 AI 助手看的 `CLAUDE.md` 都没有进副本。
    - 替换了 1 处敏感内容，用户名不再出现。

    已知边界只有一条：同事会看到这个文件夹路径。

    - 你的原项目只多了一处改动：`.gitignore`是这次新建的，里面只有 `output/deliver/` 这一行，避免副本被当成项目本身的内容。其余原文件都没动。
    - 这次的选择已经记下来，下次打包默认沿用。想全部重来，删掉 `output/deliver/_state.json` 即可。

    我没有替你发送或上传任何东西。
```

每次都一样的是这几步的顺序和一览表的三个部分（一句总数、结构表、需要你看的文件）；表里的文件、数字、待裁决的条目和助手的措辞随项目而变。实际输出里，表中的文件夹和文件名是可以点开的链接。

用户的操作：说一句话，回答给谁用，阅读清单，回复一次确认。

## 它做什么

1. **扫描并给出一览表。** 按项目的文件夹结构列出每个文件怎么处理，哪个文件有什么问题一眼可见，文件夹和文件名都可以直接点开：

   共 10 个文件：复制 6 个（其中替换敏感内容 1 个、含本机路径待裁决 1 个），不进副本 4 个（其中 3 个可以要求保留）。

   | 项目结构 | 处理 | 说明 |
   |---|---|---|
   | .claude/agents/（2 个文件） | 不进副本 | AI 协作文件，可要求保留 |
   | docs/ | | |
   | 　　guide.md | 复制 | |
   | 　　setup.md | **复制，待你裁决** | 含本机路径（不会自动替换）：Windows 本机路径 ×1 |
   | node_modules/ | 不进副本 | 整个文件夹跳过，未逐个扫描 |
   | src/ | | |
   | 　　core/ | | |
   | 　　　　a.py | 复制 | |
   | 　　　　config.py | **复制并替换** | 将替换：Windows 用户目录路径 ×1 |
   | 　　main.py | 复制 | |
   | .env | 不进副本 | 密钥或密码文件 |
   | CLAUDE.md | 不进副本 | AI 协作文件，可要求保留 |
   | README.md | 复制 | |

   需要你看的文件（2 个）：docs/setup.md、src/core/config.py

   去向相同且没有问题的文件夹会折叠成一行；有问题的文件永远单独列出。

2. **等你确认。** 需要你拿主意的条目逐条列出。没有你的明确同意，不会生成任何文件。
3. **生成副本。** 放在项目内的 `output/deliver/<档位>-<时间戳>/`，这个目录本身就是成品，可以直接提交到版本库或整目录拷走。

## 两档受众

使用时必须说明给谁用，助手不会替你猜。

| | 给开发者 `dev` | 给使用者 `user` |
|---|---|---|
| 适合 | 对方要看代码或接着改 | 对方只是使用或阅读 |
| 源码、测试、构建脚本 | 带 | 默认不带 |
| 文档 | 根目录说明文档和整个 `docs/` | 只带说明、许可、上手指南等面向使用者的部分 |
| 额外动作 | 无 | 可运行的程序会生成双击启动文件；报告、论文、PPT 只带你点名的成品 |

两档的脱敏规则完全相同。

**要打包的项目本身是一个 skill 时**：给使用者档会自动认出 skill 所在的文件夹（靠其中的 `SKILL.md`），带上里面除测试外的全部文件和项目根的说明、许可文件，并把这个文件夹作为副本的根——对方拿到后放进自己的 skill 目录就能用。认出的结果会先在报告里给你确认。

## 会处理什么

- **整个文件不带**：密钥与密码文件（`.env`、`*.pem` 等）、版本库目录、依赖与缓存目录、编辑器和系统文件、日志与临时文件、AI 协作文件（可要求保留）。
- **替换文件里的内容**：主流厂商的密钥、用户目录路径里的用户名、邮箱地址、内网地址。
- **只提示、由你决定**：自定义盘符或目录下的本机路径。它们可能是有意写的示例，所以不自动替换。
- **Office 文档**：清除 docx、pptx、xlsx 文档属性里的作者、公司、模板信息；批注、修订等内部痕迹只报告数量。

查不到的内容（例如 PDF、图片、Office 正文）见 [`references/known-limits.md`](references/known-limits.md)。

## Runtime 支持

三个工具上用的是同一套说明书和脚本。deliveryman 只需要助手能读文件、能运行 Python 命令，没有用到某一个工具独有的功能。

### ✅ Claude Code

- 安装位置：`~/.claude/skills/deliveryman/`（所有项目都能用），或 `<你的项目>/.claude/skills/deliveryman/`（只在这个项目里用）。
- 项目说明文件：`CLAUDE.md`。
- 触发：说出「触发」一节里的任意一句话，或输入 `/deliveryman dev`、`/deliveryman user`、`/deliveryman all`。

### ✅ Codex CLI

- 安装位置：`~/.agents/skills/deliveryman/`，或 `<你的项目>/.agents/skills/deliveryman/`。
- 项目说明文件：`AGENTS.md`。
- 触发：说出「触发」一节里的任意一句话。

### ✅ OpenCode

- 安装位置：`~/.config/opencode/skills/deliveryman/`，或 `<你的项目>/.agents/skills/deliveryman/`。
- 项目说明文件：`AGENTS.md`。
- 触发：说出「触发」一节里的任意一句话。

各工具的项目说明文件和配置目录（`CLAUDE.md`、`AGENTS.md`、`.claude/`、`.codex/` 等）在打包时都算 AI 协作文件，默认不进副本，可以要求保留。

## 安装

需要 Python 3.9 或更高版本。脚本只用 Python 自带的库，不需要另外安装任何包。

### 一键安装

```bash
npx skills add SEAMAN9000/deliveryman
```

需要先装好 Node.js。安装器会检测本机装了哪些 AI 编程工具，并把 skill 装到各自的位置。默认装到当前项目；加 `-g` 装到用户目录，所有项目都能用；加 `-a` 可以指定只装给某些工具。

不用安装器时，按下面的小节手动安装：用 git 把仓库直接下载到所用工具的 skill 目录，需要先装好 git。命令装到用户目录，所有项目都能用；只想在某个项目里用，把目标位置换成上一节里的项目内位置。

### Claude Code

```bash
git clone https://github.com/SEAMAN9000/deliveryman ~/.claude/skills/deliveryman
```

确认装上了：在任意一个项目文件夹里新开一个对话，输入 `/deliveryman dev`，助手给出一张一览表并等你确认，就是装上了。

### Codex CLI

```bash
git clone https://github.com/SEAMAN9000/deliveryman ~/.agents/skills/deliveryman
```

文件名必须保持 `SKILL.md`，不要改名。

确认装上了：在任意一个项目文件夹里新开一个对话，说「帮我弄一个干净的版本」，助手先问你给开发者还是给使用者，就是装上了。

### OpenCode

```bash
git clone https://github.com/SEAMAN9000/deliveryman ~/.config/opencode/skills/deliveryman
```

确认装上了：办法与 Codex CLI 相同。

|---|---|
| `/deliveryman` | `/deliveryman` |
| 弄一个干净的版本 | make a clean copy to share |
| 发给同事前清理一下 | sanitize this project before sharing |

不会触发的说法：只让助手检查或修改某个文件（例如「帮我看看 README 里有没有错别字」），或只要求上传、推送。

## 使用

在要分享的项目里：

```
/deliveryman dev
/deliveryman user
/deliveryman all
```

`all` 表示两档各做一份。也可以直接用自己的话说，例如"把这个项目弄一个干净版本发给同事"，助手会先问你给谁用。

常用的调整，都可以直接用话说：

- "把 CLAUDE.md 也留下"
- "把 notes/ 也去掉"
- "全部重审"——忽略以前接受过的裁决，逐条重新过一遍

你确认过的裁决会记在 `output/deliver/_state.json`，下次打包时只突出新出现的问题。删除这个文件即整体重置。

## 项目配置（可选）

没有配置也能用。需要长期生效的设置写在项目根的 `deliver.config.yaml`：

```yaml
custom_redactions:             # 项目专属的替换规则
  - name: internal_id
    pattern: '\bMYCO-\d{6}\b'
    replacement: '<REDACTED>'

keep:                          # 一定保留
  - docs/architecture.md

remove:                        # 一定去掉
  - notes/personal.md

user:
  entry: dist/app.exe          # 声明入口 = 这是个可运行的程序
  # artifacts: ["reports/**/*.pdf"]   # 或者点名要交付的成品文件
```

完整字段见 [`templates/deliver.config.example.yaml`](templates/deliver.config.example.yaml)。

## 跑完之后

**流程**

1. 助手只读扫描项目，给出一览表。扫描在本机完成，几十个文件的项目不到一秒。
2. 助手逐条列出需要你拿主意的条目，等你回复。这是唯一需要你确认的一步，时间主要花在你阅读报告上。
3. 你同意后，助手生成副本。给使用者档的可运行程序还会多一步生成双击启动文件；项目配置里写了构建命令时，助手会先把命令原文给你看，你同意后才运行。
4. 助手报告副本的位置、文件数、替换了多少处，以及你接受原样进入副本的条目。

**产物**

```
你的项目/
├── .gitignore                         # 首次运行时末尾多一行 output/deliver/
└── output/deliver/
    ├── dev-2026-01-15-1030/           # 副本，文件夹名是「档位-时间戳」
    ├── _reports/                      # 扫描报告、运行记录、你确认时的原话
    ├── _state.json                    # 你确认过的裁决，下次沿用
    └── deliver.config.suggested.yaml  # 只在本次临时多留或多去掉文件时生成
```

可运行程序的副本里另有 `RUN.bat` 和 `run.sh` 两个启动文件。三个工具上的产物相同。

**改动范围**

会改：`output/deliver/` 之下的文件，以及 `.gitignore` 末尾的那一行。不会改：项目里的其他任何文件，包括 `deliver.config.yaml`。

**失败时**

- 你还没确认，或确认之后又重新扫描过：生成脚本拒绝执行，不产生任何文件。
- 生成中途个别文件出错：出错的文件会列出来，完整的错误信息在 `output/deliver/_reports/` 下。这时带时间戳的副本文件夹可能不完整，不要拿去分享。
- 重来：源项目没有被改动，直接重新运行即可。每次运行生成一个新的带时间戳的文件夹，不完整的那个可以删掉。

## 三条承诺

- **源项目只读。** 所有写入都落在 `output/deliver/` 之下，脚本会拦截越界写入。唯一例外是首次运行时在 `.gitignore` 末尾追加 `output/deliver/` 一行。
- **先报告，确认后才生成。** 生成副本的脚本必须带上你确认时的原话才会执行。
- **不上传。** 只生成本地副本，不推送、不创建代码仓库。

## 目录结构

```
deliveryman/
├── SKILL.md          # 给助手看的操作说明
├── references/       # 按需读取的补充说明
├── rules/            # 脱敏规则：排除哪些文件、替换哪些内容、各档带哪些文件
├── scripts/          # 扫描、生成副本、生成启动文件的脚本
└── templates/        # 配置示例与启动文件模板
```
